klin is a starter for full-stack TypeScript products. One command —
`npm create klin@latest` — hands you a monorepo with an API, a web app, sign-in,
a database and one set of Zod schemas shared by both apps, wired end to end and
passing its own typecheck, lint, tests and build. Then the `klin` CLI stays in
the project to keep adding to it.

```bash
npm create klin@latest
```

You can [try the wizard on the home page](/#wizard) without installing
anything: it's the real CLI, running in your browser.

## The idea

**One Zod schema should describe a piece of data everywhere.** It validates the
form, validates the request, shapes the response and gives both apps their
types. Schemas live in `packages/validators`; a NestJS API turns them into DTOs
with nestjs-zod, a plain Express or Fastify API parses with them directly, and
`klin generate` writes whole features on top of them. Read
[One schema everywhere](/docs/project/shared-schemas/) for the details.

flags.

## Is it for you?

**A good fit for** SaaS products, internal tools, dashboards and API-backed apps
where a separate backend is a feature, not overhead.

**Not for** static sites, or projects that want everything — data access
included — inside one Next.js app. klin can render the web app with Next.js,
but the API stays its own app. If you'd rather have no API at all, use a
framework built for that.
