`klin generate` now writes skeletons instead of finished features, and comes in three kinds: `resource` (Prisma model, Zod schemas, API and web feature), `backend` (a NestJS controller with the five REST endpoints, service, nestjs-zod DTOs and a module registered in `app.module.ts` — or plain Express/Fastify routes and a service) and `frontend` (a page, its route, TanStack Query hooks, a form and a sidebar entry); `backend` and `frontend` also write the schemas in `packages/validators`, and reuse them when the other side made them first. Slashes in the name make organization folders in every layer (`klin generate backend loan/payment` → `modules/loan/payment/`, `validators/src/loan/payment.ts`, `/api/loan/payment`), reusing a folder that's already there. `klin generate` with no arguments asks what to make and what to call it; `klin generate <kind> <name>` (aliases `r`, `b`/`api`, `f`/`web`) does it in one line. The CLI no longer asks for fields: one example `name` field shows where yours go, backend-only services answer 501 until you fill them in, and names that would clash with existing schemas, models or modules are refused up front. New flags shape the output: `--url <path>` serves it somewhere other than its folders, `--plural <word>` fixes a wrong plural, and `--no-model`, `--no-validation`, `--no-route` and `--no-nav` skip the Prisma model, the schema file, the page's route or the sidebar entry. Where each layer's files go can change too: `--backend-dir`, `--frontend-dir`, `--validation-dir` and `--model-dir` for one run (or the new "Where should it go?" page in `klin generate`), and `klin generate paths` (or "Change default paths") for the project's defaults, saved in `klin.json` under `generate.paths`. Folders are checked before anything is written: from the project root, no `..`, inside the layer's source folder and out of `routes/` and `migrations/`. `--scope`, `--no-api` and `--no-ui` are gone.
