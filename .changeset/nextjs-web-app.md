The web app can now run on Next.js instead of Vite: pick "Next.js" under "Web app" on the Stack step, or pass `--web next`. The API, the shared packages and every module stay the same; `apps/web` becomes a Next.js 16 App Router app with `(public)`, `(auth)` and `(app)` route groups. `src/proxy.ts` sends visitors without a session cookie to `/sign-in?redirect=…`, the `(app)` layout asks the API whether the session is real and hands it to React Query so the shell renders with the user right away, and `next.config.ts` rewrites `/api` to the API (`API_URL`, defaulting to `http://localhost:$API_PORT`), so auth cookies stay first-party. TanStack Query and Form, the shadcn/ui kit (with `"use client"` where shadcn puts it, in `apps/web` or `packages/ui`), i18n (the language is kept in a cookie so the server renders in it), Playwright and CI work as they do with Vite; typed routes are on. The Docker image is Next's standalone server, and `docker-compose.prod.yml` puts nginx in front of it so the API's rate limits see each visitor's address. `klin generate` writes an App Router `page.tsx` and adds the page to `proxy.ts`'s matcher, and runs `next typegen` afterwards. The web framework is picked once: `klin add` won't switch it, and `klin list` says so. Signing out now loads `/sign-in` from scratch in both web apps, which also fixes an error the signed-in layout threw while signing out.
